# Обновление одним скриптом

Из корня проекта:

```bash
./scripts/deploy.sh --check  # тесты и сборка, сервер не используется
./scripts/deploy.sh          # проверка + обновление root@192.168.1.206
```

При первом использовании нужны локальные Python 3.11+ с модулем venv, Node.js/npm, OpenSSH, tar, sha256sum и доступ к реестрам pip/npm. Python-зависимости автоматически устанавливаются во временное окружение; `npm ci` использует зафиксированный package-lock.json. Исходники и локальный node_modules не меняются. Для ускорения можно передать `PYTHON=/absolute/path/to/venv/bin/python` с установленным `backend/requirements-dev.txt`.

## SSH без пароля в скрипте

Один раз настройте ключ и проверьте отпечаток сервера при первом подключении:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/pact_deploy
ssh-copy-id -i ~/.ssh/pact_deploy.pub root@192.168.1.206
ssh-add ~/.ssh/pact_deploy
ssh -i ~/.ssh/pact_deploy root@192.168.1.206 true
DEPLOY_IDENTITY="$HOME/.ssh/pact_deploy" ./scripts/deploy.sh
```

Для ключа с парольной фразой требуется ssh-agent с загруженным ключом. Скрипт использует BatchMode и StrictHostKeyChecking=yes: не спрашивает и не хранит пароль сервера, не принимает неизвестный ключ автоматически. SSH-алиас можно задать как `DEPLOY_HOST=pact-server`. Альтернативный файл настроек: `DEPLOY_SSH_CONFIG=/путь/к/config`. Если системный SSH-конфиг сообщает об ошибке владельца/прав, можно использовать `DEPLOY_SSH_CONFIG=/dev/null` и явно передать ключ.

## Что делает обновление

1. Создаёт неизменяемый локальный снимок исходников, запускает backend-тесты, тесты deploy-транзакции и frontend-тесты, собирает интерфейс.
2. Передаёт только runtime-код, шаблоны, готовый frontend и скрипты. Исходные документы клиентов, .env, базы, node_modules и тестовые данные в пакет не попадают.
3. Проверяет SHA-256 пакета. Подготавливает `/opt/pact/releases/<дата-хеш>` и отдельное Python-окружение, пока прежнее приложение работает.
4. Останавливает запись, сохраняет базу и документы в `/var/backups/pact/<дата-хеш>`, проверяет контрольные суммы.
5. Переключает `/opt/pact/backend`, `frontend`, `templates`, `scripts` и `.venv` на новый выпуск через ссылки. Исходная установка с обычными каталогами поддерживается: прежние пути перемещаются в `<дата-хеш>.previous`.
6. Запускает pact и проверяет API с подключением к БД, главную страницу и доступность JS/CSS. При сбое возвращает прежние пути и перезапускает старую версию. Если откат тоже не проходит проверку, сообщает об этом и завершается с ошибкой.

База и `/var/lib/pact/documents` не заменяются при откате. Изменения схемы БД требуют отдельной процедуры миграции: этот скрипт не делает обратных миграций. Nginx, сертификаты, `/etc/pact.env` и systemd unit приложения не заменяются.

Обновление выполняется системной службой `pact-deploy-<дата-хеш>`, чтобы разрыв SSH не прервал переключение файлов. При потере связи не запускайте повторно вслепую: проверьте состояние сервиса и журнал на сервере:

```bash
systemctl list-units 'pact-deploy-*' --all
journalctl -u 'pact-deploy-*' --since today
systemctl status pact
```

На время копирования данных и перезапуска возможна недоступность сайта. Параллельные deploy/backup блокируются flock. Ежедневный таймер копирования временно приостанавливается и затем возвращается в прежнее состояние. Старые выпуски и копии автоматически не удаляются: контролируйте свободное место. После аварийного выключения сервера во время переключения может потребоваться ручное восстановление из каталога `.previous`.

## Изменение шаблонов

Побайтовое отличие рабочих DOCX от серверных блокирует обновление до явного подтверждения проверки:

```bash
./scripts/deploy.sh --templates-reviewed
```

Используйте флаг только после генерации контрольных DOCX/PDF и просмотра всех страниц. Сам скрипт проверяет целостность шаблонов, но не заменяет визуальную проверку.

## Проверка самого скрипта

```bash
bash -n scripts/deploy.sh scripts/deploy-remote.sh scripts/backup-native.sh
python3 scripts/tests/test_deploy.py
```

Три теста выполняются в временном каталоге с имитацией systemd/PostgreSQL: успешное переключение, сбой backup, неуспешная проверка новой версии с откатом. Рабочий сервер ими не затрагивается.
